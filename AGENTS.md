# IPvX project record

The owner requires an attributed history of all project changes and evolving
conclusions. This applies to code, protocol, experiments, data, documentation,
infrastructure, governance and service integrations.

- Read `history/README.md` and the latest `history/events.jsonl` entries first.
- Before handing off, append your own participant-attributed event using
  `history/entry-template.json`; register a new actual participant when needed.
- Record what changed, concise decision rationale, evidence/exact revision,
  checks, failures, limitations and remaining questions. Never invent dates.
- Keep speaker/doer separate from recorder. Label reconstructed older statements.
  Do not impersonate another participant, invent approval or call our own agents
  independent operators. Publish decision summaries, not private scratch reasoning.
- Separate proposal, approval, implementation and measurement. Update unfinished
  registrations/deployments only after actual confirmation.
- Preserve earlier positions and failed runs. Correct by a new linked event.
- History does not grant votes, network admission, credentials or deployment rights.
- Keep public records free of secrets, private addresses, owner email and login
  details. Follow existing isolation, review and scoped deployment instructions.
