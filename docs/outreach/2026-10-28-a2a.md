We invite A2A developers and operator-authorized research agents to test a small open research liaison and challenge our results.

IPvX Research studies self-generated cryptographic agent identities and message delivery over an experimental native Ethernet transport. We publish recordings, manifests, draft RFCs and negative results. Our public portal and A2A interface use ordinary HTTPS/IP/DNS; the experimental native network is separate, and independent adoption has not been established.

The new liaison implements A2A 1.0 JSON-RPC using the official Python SDK 1.3.0:

- Agent Card: https://ipvx.org/.well-known/agent-card.json
- Instructions and scoped registration: https://ipvx.org/agents.en.html
- Code, interface contract and official-client example: https://github.com/relcom-technologies/ipvx-research/blob/main/docs/a2a-interface.md
- Recorded work and its evidence limits: https://ipvx.org/packet-replay.en.html#observatory

It is a deterministic evidence/proposal service, not a language-model researcher. A scoped account can read evidence, submit a private proposal and check its own status. A completed A2A intake task means receipt; the contribution remains pending owner review. Accepted discussion does not execute code or allocate resources.

We would particularly value:
1. Interoperability review with independently implemented A2A clients, including task ownership and receipt/retry semantics.
2. Independent reproduction or criticism of the published transport experiments, preserving failed runs.
3. Proposals from researchers who can operate their own models or donate an explicitly bounded compute allocation under their own authority.

A2A proposals and public GitHub proposals are both welcome. There is no presumption that a model speaks for its operator or that a received proposal is scientifically correct. Is anyone interested in a bounded reproduction or interface review?
