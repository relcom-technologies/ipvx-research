# IPvX research portal

Mode: Read. This separate public static portal inherits the Operating Sheet identity: local Plex, stone/white/ink/ochre, flat surfaces and thin rules. The implementation extends the identity for research reading; it is not the private management UI. No formal seeded five-block direction card was supplied, and this brief does not record an approval that did not occur.

Confirmed purpose: both research evidence and demonstrations, with collaborative RFC development at the center. Researchers may propose a task, protocol change or their own model. Admission of a contribution or model requires more than half of the eligible roster; a vote does not grant machine access or keys. The disclosed bootstrap electorate is one owner. Every current RFC is Draft. Primary actions: read draft RFCs and prepare a public GitHub proposal.

Implemented composition: a normal-flow name/header and research navigation; a twelve-column index with an eight-column name band and four-column scope disclosure, four equal navigation rails, then an eight-column mechanism cell and four-column RFC invitation. Stone gutters join square white cells. The ordinary-web boundary appears in the scope cell before the protocol explanation: the portal and management use IP/DNS/HTTPS, while native delivery belongs to a controlled experiment. There is no pinned scrolling, private sidebar, launch console or live event journal.

The signature material has two distinct levels. The A → R1 → B component is an explicitly labelled interactive explanation: four keyboard-operable steps show who chooses the next hop and where the model executes. It links to a real saved-exchange page containing task text, receiver output, timing, signed-hop/receipt envelopes and verification downloads. Public proof exports include only public identity/verification-key pins and audited native signed envelopes, with no contact roster or internal IP addresses. Signatures bind the chain to ciphertext hashes; displayed plaintext is matched to an owner-collected log, without a public decryption proof or independent attestation. Do not collapse these limits into an end-to-end plaintext proof claim.

Reading contract: 13 static pages—overview, architecture, experiments, RFC index, publications, participation, governance, reproducibility, four RFC documents and the saved exchange. All primary navigation and saved evidence work without JavaScript. Static LLM results, table, conclusion and limitations remain visible if the optional JSON refresh fails. Native measurement, local model comparison, process-only document work and simulation retain their separate evidence labels and limits. Sources are the project's actual experiment exports, public papers and its own trace geometry; no stock cloud imagery, invented researchers or external adoption claims.

Contribution boundary: the form prepares a GitHub issue; external submission is explicit. Eligibility and votes are handled in GitHub and fail closed when eligibility is unknown. The public site never executes a proposed model or issues infrastructure credentials. DNS/hosting details are operational context, not evidence of protocol capability or independent participation.
