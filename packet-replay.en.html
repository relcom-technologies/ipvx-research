    What happened when R stopped

    In the negative run, R was stopped after the network interfaces were ready. The capture contains HELLOs and delivery attempts; no task completed. This topology has no backup link, so the route did not recover.

    The exact time R stopped was not recorded as a separate PCAP event. The replay does not invent it: frames and A's timeout in the console log are available.

    Timing and evidence limits

    The two PCAP clocks belong to different guests: they cannot be subtracted to estimate a hop. The order preserves each link's queue and matching tasks/results at R's two ports. The global order of repeated HELLOs is not established. The moving dot does not measure link latency.

    The exporter verified every frame: boundaries, CRC, Ed25519, the ID–public-key match, recipient and payload. The browser displays the saved result of that verification. There is no encryption; keys are held in memory, trust is on first contact, and forwarding uses a predefined table.

    Native delivery across five ordinary VMs with LLMs is a different, earlier experiment: their OSes retain IP for management. These results are not combined as proof of LLM execution inside a strict OS.

    AI on separate machines

    Completed paired experiment: 4 collaborative tasks and 48 signed deliveries per mode. Final answers matched between modes in all four cases; 2 of 4 decisions in each mode matched the reference.

    Two local Qwen3-0.6B Q8_0 models, three guest OSes on three different physical hosts, one operator. Native guest kernels have no INET/IPv6 or loadable modules. Management of the surrounding machines uses IP; TCP/IP is not disabled on the physical hosts.

    Echo · median

    12.11 ms IPvX · 20.98 ms IP

    AI task · median

    36.25 s IPvX · 35.94 s IP

    Echo is faster through IPvX in this sample; acceleration of the collaborative AI task is not established. Model inference takes seconds. The IP control uses the same application nodes A–R–B: this is not a comparison with direct IP. Only 40 echoes and four tasks per mode.

    Order: IPvX → IP, then IP → IPvX. Identical weights, keys, allocated memory and processors. Guest clocks receive their initial time from a local virtual device; latencies use monotonic clocks. All previous services were restored after the experiment.
