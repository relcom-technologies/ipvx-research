RFC-0003 — Teilnahme und Mehrheitszustimmung

IPvX-Arbeitsdokument · Entwurf · offen zur Diskussion

RFC-DiskussionOriginaltext

Status: Entwurf. Die Mehrheitsanforderung des Eigentümers ist für die Projektzulassung bindend. Die folgenden detaillierten Anfangsregeln sind ein vorläufiger Implementierungsvorschlag und keine Behauptung gemeinschaftlicher Ratifizierung.

Teilnahme

Jeder kann die öffentlichen Materialien lesen und einen öffentlichen Vorschlag einreichen. Vorschläge betreffen RFCs, Experimente, Modelle oder Änderungen der Mitgliederliste. Niemals API-Schlüssel, private Schlüssel, vertrauliche Datensätze oder uneingeschränkt aufrufbare Endpunkte einreichen.

Stimmberechtigte und Schwelle

Das aktuelle Wahlgremium besteht aus den menschlichen GitHub-Konten in governance.json. Anfangs enthält es nur den Projekteigentümer ashkitt: eine berechtigte Person, Schwelle eins. Dies ist ausdrücklich eine Aufbauphase. Modellinstanzen und doppelte Konten erhalten durch ihre Verbindung keine Stimmen.

Das Gremium für einen Vorschlag wird auf den governance.json-Commit bei Eröffnung festgelegt. Zustimmung erfordert mehr als die Hälfte ALLER berechtigten Konten, nicht nur die Mehrheit der Abstimmenden. Enthaltung oder Nichtabstimmung verringern die Schwelle nicht. Das vorläufige Abstimmungsfenster beträgt 72 Stunden ab Issue-Erstellung ohne vorzeitige Zustimmung. Eine spätere Mehrheit kann diese Richtlinie über einen Gremiums-/Richtlinienvorschlag und eine geprüfte Änderung revidieren.

Stimmen

Berechtigte Personen kommentieren genau /vote yes, /vote no oder /vote abstain im Vorschlags-Issue. Nur authentifizierte GitHub-User-Kommentare zählen; verwendet wird der letzte gültige Kommentar je Person innerhalb des Fensters. Verspätete Kommentare, Bots, Fließtext und unberechtigte Konten zählen nicht. Der geplante Workflow kennzeichnet das aktuelle Abstimmungsergebnis; Kommentare und Mitgliedschaft sind öffentlich nachprüfbar. Ein fehlgeschlagener Workflow ist keine Zustimmung.

Getrennte Freigaben

Eine Mehrheitskennzeichnung genehmigt grundsätzlich die Forschungszulassung. Sie führt keinen Code zusammen, veröffentlicht keinen RFC, startet kein Modell und vergibt keine Zugangsdaten. Ein Maintainer prüft weiterhin Reproduzierbarkeit, Lizenzierung, Ressourcengrenzen und Isolation und führt dann die begrenzte Bereitstellung über eine geprüfte Änderung aus. Der RFC-Status bleibt Entwurf, bis die akzeptierte Revision und der Beschluss protokolliert sind. Eine externe Maschine kann lokal experimentieren, ohne zu diesem privaten Labor zugelassen zu sein.

Offene Governance-Fragen

Berufungen, Entfernung inaktiver Mitglieder, Interessenkonflikte, Finanzierung und Rechenkontingente, doppelte Mitgliedschaften, Notfallsperren und langfristige Freigabehoheit bedürfen öffentlicher Diskussion. Dieses erste Portal behauptet nicht, diese Fragen seien geklärt.

Originaldokument

Status: Draft. The owner's majority requirement is binding for project admission. The detailed bootstrap rules below are a provisional implementation proposal, not a claim of community ratification.

Participation

Anyone can read the public materials and submit a public proposal. Proposals cover an RFC, an experiment, a model or a roster change. Never submit an API key, private key, confidential dataset or unrestricted callable endpoint.

Electorate and threshold

The current electorate is the human GitHub accounts in governance.json. Initially it contains only the project owner, ashkitt: one eligible person, threshold one. This is explicitly a bootstrap phase. Model instances and duplicate accounts do not gain votes by being connected.

The electorate for a proposal is pinned to the governance.json commit at proposal opening. Approval requires more than half of ALL eligible accounts, not just a majority of those who voted. An abstention or no vote does not reduce the threshold. The provisional voting window is 72 hours from issue creation, with no early approval. A future majority can revise this policy through a roster/policy proposal and reviewed change.

Votes

Eligible people comment exactly /vote yes, /vote no or /vote abstain on a proposal issue. Only authenticated GitHub User comments count; the latest valid comment per person within the window is used. Late comments, bots, prose and ineligible accounts do not count. The scheduled workflow labels the current vote result; comments and membership are publicly inspectable. A failed workflow is not an approval.

Separate gates

A majority-approved label authorizes research admission in principle. It does not merge code, publish an RFC, run a model or issue a credential. A maintainer still reviews reproducibility, licensing, resource limits and isolation, then performs the scoped deployment through a reviewed change. RFC status remains Draft until the accepted revision and decision record are committed. An external machine can run an experiment locally without being admitted into this private lab.

Open governance questions

Appeals, removing inactive members, conflict of interest, funding and compute quotas, membership duplication, emergency suspension and long-term release authority require public discussion. This first portal does not pretend those questions are settled.
