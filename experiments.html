BCP 0.2

BCP 0.2 — пакетный слой и реестр IPvX. Контракты реестра проверены на живой цепочке Sepolia: REG-001 шёл в режиме чтения Q, а R1 закрыт 2026-11-06 чтением REG-001-LC через лёгкий клиент — по заменённому критерию, текущему состоянию; значения S1–S3 остаются наблюдениями режима Q. Доставка пакетов по реестру (NET-001) ещё не запускалась.

Снимок состояния: 2026-11-08

Реализовано в коде

Формат пакетов, NodeRegistry, TransitPolicy, ConnectionPolicy, EL/CL-адаптер и связь с ядром. Чтения контрактов привязаны к одному финализированному blockHash.

Проверено офлайн

91 тест runner и 14 проверок плана. Временные ключи, EVM в памяти, синтетические заголовки и memory ports; это не измерение сети или финальности цепочки.

Следующий сетевой опыт

NET-001: протокол принят в двух вариантах — на тестовом и на живом состоянии реестра; ни один ещё не запускался. Живой вариант читает реестр через лёгкий клиент Helios: режим LC заменил режим V 2026-11-05, собственный узел Sepolia не нужен. Helios на стенде не работает: временный клиент, выполнивший чтение, удалён. Отдельная ВМ стенда выделена: 2026-11-08 на ней три раза из трёх прошла репетиция раннера без разрешения на запуск — только работа с ядром Linux на синтетических кадрах, без ядра BCP и цепочки. Новая область закрепления исходников раннера ждёт подтверждения владельца, правило обновления снимка в NET-001-L остаётся открытым условием. Допуск к запуску закрыт.

Живой стенд: lab.ipvx.org

Отдельный живой стенд использует пять ВМ на трёх физических хостах, синтетических агентов без LLM и административный IP. Это другая конфигурация, чем записанный strict-LLM-опыт с тремя гостями без INET/IPv6. Ни тот, ни другой не реализуют блокчейн-реестр BCP; конфигурация подложки между гипервизорами отдельно не подтверждена. На lab.ipvx.org видны текущие маршруты, хронология отказа посредника и подписанные доказательства каждого перехода. Страница только для просмотра: внутренние адреса и расшифрованные результаты скрыты, отключать узлы может только оператор стенда.
