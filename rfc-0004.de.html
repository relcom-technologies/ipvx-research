RFC-0004 — Reproduzierbare Modell- und Netzbewertung

IPvX-Arbeitsdokument · Entwurf · offen zur Diskussion

RFC-DiskussionOriginaltext

Status: Entwurf · kein IETF-RFC.

Getrennte Fragen

Können unabhängige Modellprozesse zusammenarbeiten? Stellt der gewählte Transport die Nachrichten zu? Ist die endgültige Antwort richtig? Verbessert er gewöhnliches IP? Eine bestandene Frage bedeutet nicht, dass die anderen bestanden sind.

Vergleich unter gleichen Bedingungen

Modellgewichte und Hashes, Laufzeit, Prompt, Seed, Nachweise, Tokenlimit und Hardware festschreiben. Natives Ethernet A–R1–B, gewöhnliches IPv4/TCP direkt A–B und topologiegleiches IPv4/TCP A–R1–B ausführen. Gleiche Anwendungsidentität, Verschlüsselung und Bestätigungen beibehalten. Reihenfolge abwechseln. Erklärte Aufwärmphase ausschließen. Bei jedem Versuch frische Inferenz messen; wiedergegebene Antworten nicht als neuen Modelllauf melden.

Gemeinsame Aufgabe

A erstellt eine Forschungsbewertung anhand von Messungen; B kritisiert sie anhand separat vorgeladener Einschränkungen; A synthetisiert die endgültige Entscheidung. Nachrichten tragen Aufgaben-IDs und strukturierten Text, keine Webseiten. Die Warteschlangenbestätigung erfolgt sofort; die Modellinferenz läuft asynchron. Der Koordinator startet und beobachtet das Experiment lediglich.

Bericht

Modellausgaben einschließlich Fehlern, Prompts und Hashes, signierte Zustellspuren, auf das Experiment gefilterte Frame-Mitschnitte, Tokenzahl und Inferenzzeit je Aufruf, Gesamtdauer der Aufgabe sowie Netzwerk-RTT bei fester Nutzlast veröffentlichen. Stichprobengröße, Hop-Zahl, Betreiberzahl und jede weiterhin IP-basierte Infrastrukturunterlage angeben.

Grenzen des aktuellen lokalen Modells

Qwen3-0.6B Q8_0 ist ein tatsächliches offenes Sprachmodell, das auf die vorhandenen CPU-VMs passt. Ein Ergebnis mit diesem kleinen Modell belegt kein Verhalten großer Spitzenmodelle, unabhängiger Organisationen oder des öffentlichen Internets. Größere und von Forschern bereitgestellte Modelle benötigen neue genehmigte Experimente, keine Hochrechnung.

Originaldokument

Status: Draft · not an IETF RFC.

Separate questions

Can independent model processes collaborate? Does the selected transport deliver the messages? Is the final answer correct? Does it improve on ordinary IP? A pass on one question is not a pass on the others.

Matched comparison

Freeze model weights and hashes, runtime, prompt, seed, evidence, token limit and hardware. Run native Ethernet A–R1–B, ordinary IPv4/TCP directly A–B, and matched-topology IPv4/TCP A–R1–B. Keep the same application identity, encryption and receipts. Alternate the order. Exclude declared warm-up. Measure fresh inference on every trial; do not report replayed answers as a new model run.

Collaborative task

A drafts a research assessment using measurements; B critiques it using separately preloaded limitations; A synthesizes the final decision. Messages carry task IDs and structured text, not websites. Queue acknowledgement is immediate; model inference runs asynchronously. The coordinator only starts and observes the experiment.

Report

Publish model outputs including errors, prompts and hashes, signed delivery traces, frame captures filtered to the experiment, per-call token and inference time, task makespan and fixed-payload network RTT. State sample size, hop count, operator count and whether any infrastructure underlay still uses IP.

Current local model boundary

Qwen3-0.6B Q8_0 is an actual open language model chosen to fit existing CPU VMs. A result with this small model does not establish behavior of frontier models, independent organizations or the public Internet. Larger and researcher-supplied models need new approved experiments, not extrapolation.
